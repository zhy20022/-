## 🔍 问题原因分析

### 原因1：统计数据分散存储
- **战斗数据**：存储在 `DungeonProgressModel` 中，但需要聚合统计
- **角色数据**：存储在 `CharacterModel` 中，需要查询统计
- **击杀数据**：未持久化，只在战斗过程中临时计算

### 原因2：缺少统一的统计查询方法
- 没有专门的统计查询函数
- 每次需要统计数据时都要写重复的查询代码
- 不同接口使用不同的统计方式

### 原因3：缺少玩家统计汇总表
- 没有 `PlayerStatisticsModel` 这样的汇总表
- 统计数据需要实时计算，性能可能受影响
- 无法快速获取玩家的整体统计数据

---

## 💡 解决方案选项

### 方案A：实时统计查询（推荐用于小规模数据）

**优点：**
- 数据准确，实时反映最新状态
- 不需要额外的表结构
- 实现简单

**缺点：**
- 每次查询都要计算，性能可能受影响
- 如果数据量大，查询可能较慢

**实现方式：**
```python
def get_player_statistics(player_id: str) -> Dict[str, int]:
    """从数据库实时统计玩家数据"""
    db = get_database()
    session = db.get_session()
    
    # 统计战斗完成数（所有副本的总挑战次数）
    battles_completed = session.query(
        func.sum(DungeonProgressModel.total_attempts)
    ).filter(
        DungeonProgressModel.player_id == player_id
    ).scalar() or 0
    
    # 统计副本完成数（所有副本的完成次数总和）
    dungeons_completed = session.query(
        func.sum(DungeonProgressModel.completion_count)
    ).filter(
        DungeonProgressModel.player_id == player_id
    ).scalar() or 0
    
    # 统计角色数量
    character_count = session.query(CharacterModel).filter(
        CharacterModel.player_id == player_id
    ).count()
    
    session.close()
    
    return {
        'battles_completed': battles_completed,
        'dungeons_completed': dungeons_completed,
        'character_count': character_count
    }
```

---

### 方案B：创建统计汇总表（推荐用于大规模数据）

**优点：**
- 查询速度快，直接读取汇总数据
- 可以定期更新，减少实时计算压力
- 可以存储更多统计维度

**缺点：**
- 需要额外的表结构
- 需要维护数据一致性（更新统计）
- 实现相对复杂

**实现方式：**
```python
class PlayerStatisticsModel(Base):
    """玩家统计数据模型"""
    __tablename__ = 'player_statistics'
    
    player_id = Column(String(50), ForeignKey('players.player_id'), primary_key=True)
    battles_completed = Column(Integer, default=0)
    dungeons_completed = Column(Integer, default=0)
    character_count = Column(Integer, default=0)
    monsters_killed = Column(Integer, default=0)
    # ... 其他统计数据
    
    updated_at = Column(DateTime, default=datetime.utcnow, onupdate=datetime.utcnow)
```

---

### 方案C：混合方案（推荐）

**优点：**
- 结合两种方案的优点
- 可以灵活选择统计方式
- 性能和数据准确性平衡

**实现方式：**
- 创建统计汇总表（用于快速查询）
- 提供实时统计函数（用于数据验证和更新）
- 在关键操作后更新统计表
