# 八系角色从1级开始的流程检查

检查日期：2026-09-17。本轮仅增加验收脚本与报告，没有修改游戏规则、线上数据或发布版本。

## 检查后的玩家裁定

保留经验本限时清怪的通关规则，不采用“存活60秒即通关”的建议。优先让输出职业挑战同属性经验本，获得的通用经验包可分配给坦克、治疗和辅助，无需这些角色亲自通关。后续已将这条成长路线及升级同时消耗金币的说明写入新手指引；下文的生存通关建议保留为检查时的历史分析，不作为待实施方案。

## 方法与范围

- 使用隔离的本地 PostgreSQL 和正式 Nest HTTP 接口，建立64个新账号，分别验证64名角色的首抽起步。
- 临时将本地角色池限制为指定角色，以覆盖所有首抽结果；保留原抽卡价格160金币和初始100000金币，不注入经验包或成长资源。这不是自然抽卡概率测试。
- 检查注册、抽取、1级保存9槽、拒绝异属性经验本、真实战斗、结算、防重复领取、经验包与金币升级、再次挑战、重新登录读取存档。
- 共完成131场真实引擎战斗；只推进服务端等待时钟，不伪造战斗结果。每名角色最多进行3次1级挑战，能升级后再挑战一次。
- 各角色首战使用不同随机种子；下表是本轮观测结果，不代表长期胜率，也不能用不同种子的升级前后结果推断升级效果。

## 优先问题

### 1. 墨韫的1级独立成长容易停滞

HTTP验收中连续三次坚持18、12、11秒，共获得79个经验包，未能首次升级。另用默认技能配置、无装备、1级，在真实引擎中以 `newplayer-moyun-0` 至 `newplayer-moyun-19` 的20组种子复测：17次奖励0，3次各79；持续8至18秒，没有通关。

这证明存在明显的初始成长风险，但不意味着永远无法升级，也不是全部玩家的统计胜率。建议优先检查其伤害积存、生命上限变化与经验怪伤害压力，再确定采用新手基础保障还是副本分职业适配；不要未经裁定改掉角色技能。

### 2. 生存型角色的经验本目标与通关收益不一致

本轮19名角色存活到60秒但因剩余敌人而判失败，获得531经验包，却没有金币，也不增加扫荡通关进度。首战29名角色累计伤害为0；坦克、辅助的非伤害技能不一定是实现错误，但清怪型通关条件会限制其单人成长。

涉及存活到60秒仍失败的角色：江无尘、寒澈、沐霖、玉尘子、玄珞、玄渊、承霄入、殷破、夕元道人、那兰隐、沈御霄、云无羁、苏勤、肃祀生、喜诛、角赦、原伯铮、张静虚、司空朔。

当前行为符合此前“时间到仍有敌人则未通关”的规则，不宜直接判定代码错误。建议单独裁定经验本是否例外：坚持60秒即通关，清怪仅增加直接经验；五人本和团队本仍要求消灭敌人。此规则尚未修改。

相关实现：`scripts/nest_battle_worker.py`、`server-nest/src/dungeons/dungeons.service.ts`、`server-nest/src/battle-settlement/battle-settlement.service.ts`。

### 3. 新手引导和失败提示需要按真实限制修正

- 指引使用同一个浏览器存储键 `gamer_new_player_guide_v1`，没有按账号隔离；同浏览器新账号可能继承旧账号的完成状态。
- “我已挑战经验本”按钮可以直接完成对应步骤，并不验证真实挑战记录。
- “优先进入同属性”应明确为“只能进入同属性”。
- 升级说明需同时说明经验包和金币消耗。
- 经验本失败建议仍包括多带相克角色、为治疗位留槽、平均等级接近100等，不适合单角色1级新手。

相关实现：`web/src/services/newPlayerGuide.ts`、`web/src/components/NewPlayerGuide.tsx`、`web/src/pages/BattlePage.tsx`。

## 建议顺序

1. 先明确经验本的生存通关规则，确保八系坦克、输出、治疗都能独立开启成长和扫荡。
2. 针对墨韫等低生存起步角色做同种子复测和新手难度调整，保留角色设定。
3. 修正按账号隔离的真实进度指引、升级资源说明和单人经验本失败提示。
4. 再做更大随机样本的升级前后同种子比较，以及普通至困难、噩梦的长期成长验收。

初始100000金币掩盖了早期持续收入差异；本轮没有出现首次升级缺金币。不能据此断言长期金币经济已平衡。
