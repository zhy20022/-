#### 示例：任务系统页面

```
【任务系统页面】
页面路径：/quests
入口位置：主菜单添加"任务"按钮

页面布局：
- 顶部：标题"任务" + 返回按钮
- 中间：左侧任务列表（分标签：全部/主线/支线/日常/周常），右侧任务详情
- 底部：无

需要显示的数据：
1. 任务列表：从 /api/quests/list 获取
   - 任务名称、类型、状态（未解锁/可接取/进行中/已完成/已领取）
   - 任务进度（例如：3/10）
   - 任务奖励预览
2. 任务详情：点击任务后显示
   - 任务描述
   - 任务目标详情
   - 当前进度
   - 奖励详情

交互功能：
1. 点击任务：显示任务详情
2. 点击"接取"按钮：调用 /api/quests/accept，更新任务状态
3. 点击"领取奖励"按钮：调用 /api/quests/claim，领取奖励并更新状态
4. 切换标签：过滤显示不同类型的任务

样式要求：
- 任务卡片样式，已完成的任务显示灰色
- 可接取的任务高亮显示
- 奖励图标显示

参考游戏/设计：
- 参考失落的龙约的任务界面布局
```

#### 示例：任务系统自动更新

```
【系统集成】- 任务系统自动更新
触发时机：战斗结束后（无论胜利还是失败）

需要做的事情：
1. 检查玩家完成的任务目标
   - 如果战斗胜利，更新"完成副本"类任务进度
   - 更新"击杀怪物"类任务进度（根据击杀数量）
   - 更新"使用技能"类任务进度（根据使用的技能）
2. 检查任务是否完成
   - 如果任务进度达到目标，将任务状态改为"已完成"
3. 检查是否有新任务解锁
   - 根据玩家数据（等级、完成的任务数等），检查是否有新任务可接取

需要更新的数据：
- 任务进度：从战斗结果获取数据，更新到任务系统
- 任务状态：从"进行中"更新为"已完成"（如果完成）

需要调用的系统：
- QuestSystem.update_quest_progress() - 更新任务进度
- QuestSystem.check_unlocked_quests() - 检查解锁任务

是否需要持久化：
- 是：保存到数据库的 quest_progress 表（需要新建）
```

#### 示例：任务系统数据持久化

```
【数据持久化】- 任务系统
需要保存的数据：
1. 任务进度：玩家接取任务后，每次更新进度时保存
   - player_id, quest_id, current_progress, max_progress, status
2. 任务奖励领取记录：玩家领取奖励后保存
   - player_id, quest_id, claimed_at
3. 任务解锁状态：玩家解锁任务时保存
   - player_id, quest_id, unlocked_at

数据表设计：
- 表名：quest_progress
- 字段：
  - id (主键)
  - player_id (外键 -> players)
  - quest_id (任务ID)
  - current_progress (当前进度)
  - max_progress (目标进度)
  - status (状态：in_progress/completed/claimed)
  - updated_at (更新时间)
  - created_at (创建时间)

保存时机：
- 接取任务时：创建新记录
- 更新任务进度时：更新 current_progress 和 updated_at
- 完成任务时：更新 status 为 'completed'
- 领取奖励时：更新 status 为 'claimed'

读取时机：
- 玩家进入任务页面时：读取所有任务进度
- 检查任务状态时：从数据库读取最新进度
```

## 💡 提需求时的技巧

### 1. 分步骤提需求
如果功能复杂，可以分步骤：
- **第一步**：先实现核心功能（例如：先显示任务列表）
- **第二步**：添加交互功能（例如：点击查看详情）
- **第三步**：完善细节（例如：添加动画、优化样式）

### 2. 提供参考
如果参考其他游戏：
- 说明参考哪些点（布局、交互、样式）
- 说明哪些不需要（避免我误解）

### 3. 明确优先级
如果有多个需求：
- 告诉我哪个最紧急
- 告诉我可以分批次实现

### 4. 提供示例数据
如果涉及数据展示：
- 告诉我数据格式（如果有）
- 或者告诉我从哪里获取（API路径）
