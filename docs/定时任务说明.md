# 定时任务说明

## 🤔 什么是定时任务？

**定时任务**就像是一个"闹钟"，它会按照设定的时间间隔，自动执行某些操作。

### 生活中的例子
- **闹钟**：每天早上7点自动响
- **定时器**：每30分钟提醒你休息
- **自动保存**：Word文档每5分钟自动保存一次

---

## 🎮 在活动系统中的含义

### 当前情况（没有定时任务）
```
用户访问活动页面 → 服务器检查活动是否到期 → 返回活动信息
```
**问题：** 如果用户不访问页面，活动到期了也不会自动切换！

### 使用定时任务后
```
后台定时任务（每5分钟） → 自动检查活动是否到期 → 如果到期，自动切换活动
```
**优点：** 即使没有用户访问，活动也会在到期时自动切换！

## 📊 工作原理图解

### 方式A：定时任务（推荐）

```
时间轴：
00:00 ──────────────────────────────────────────> 24:00
 │      │      │      │      │      │      │
 │      │      │      │      │      │      │
定时任务每5分钟执行一次：
 ├─检查活动是否到期
 ├─如果到期 → 自动切换到下一个活动
 ├─如果未到期 → 等待下次检查
 └─5分钟后再次检查...
```

**具体流程：**
1. **00:00** - 定时任务启动，检查活动是否到期
2. **00:05** - 定时任务再次检查
3. **00:10** - 定时任务再次检查
4. **...** - 持续每5分钟检查一次
5. **如果活动到期** - 自动切换到下一个活动

## 🔄 三种触发方式对比

### 方式A：定时任务（推荐）✅

**工作原理：**
- 后台有一个"定时器"，每5分钟自动运行一次
- 每次运行时，检查活动是否到期
- 如果到期，自动切换到下一个活动

**优点：**
- ✅ 活动会在到期时**自动切换**，不需要用户访问
- ✅ 切换时间**精确**，可以控制到分钟
- ✅ 不依赖用户行为，**稳定可靠**

**缺点：**
- ❌ 需要额外的后台服务（但很简单）
- ❌ 即使没有活动到期，也会定期检查（但检查很快，不影响性能）

**适用场景：**
- 需要精确控制活动切换时间
- 希望活动自动切换，不依赖用户访问

---

### 方式B：请求时检查

**工作原理：**
- 当用户访问活动页面时，服务器才检查活动是否到期
- 如果发现活动已到期，立即切换

**优点：**
- ✅ 实现简单，不需要额外服务
- ✅ 只在需要时检查，节省资源

**缺点：**
- ❌ 如果长时间没人访问，活动不会自动切换
- ❌ 切换时间不精确，取决于用户何时访问
- ❌ 如果活动在凌晨到期，可能要等到早上才切换

**适用场景：**
- 对切换时间精度要求不高
- 可以接受活动切换延迟

---

### 方式C：混合方式

**工作原理：**
- 定时任务负责主要轮换（每5分钟检查）
- 用户访问时也检查一次（作为补充）

**优点：**
- ✅ 结合了两种方式的优点
- ✅ 即使定时任务出问题，用户访问时也能切换

**缺点：**
- ❌ 实现稍微复杂一点

**适用场景：**
- 需要高可靠性
- 希望有双重保障

## 💻 技术实现示例

### 定时任务实现（Python）

```python
# 使用 APScheduler 库实现定时任务
from apscheduler.schedulers.background import BackgroundScheduler
from datetime import datetime

# 创建定时任务调度器
scheduler = BackgroundScheduler()

def check_and_rotate_events():
    """检查并轮换活动"""
    current_time = datetime.utcnow()
    
    # 检查团队活动是否到期
    team_event = event_rotation_manager._get_team_event_for_month(current_time)
    # 如果当前活动已到期，切换到下一个活动
    # ... 切换逻辑 ...
    
    # 检查全服活动是否到期
    server_event = event_rotation_manager._get_server_event_for_quarter(current_time)
    # 如果当前活动已到期，切换到下一个活动
    # ... 切换逻辑 ...

# 每5分钟执行一次检查
scheduler.add_job(
    check_and_rotate_events,
    'interval',
    minutes=5,  # 每5分钟
    id='event_rotation_check'
)

# 启动定时任务
scheduler.start()
```

**工作流程：**
1. 服务器启动时，创建定时任务
2. 定时任务在后台运行，每5分钟执行一次 `check_and_rotate_events()`
3. 函数检查活动是否到期
4. 如果到期，自动切换到下一个活动

## ⏰ 检查频率说明

### 为什么是5分钟？

**5分钟检查一次**意味着：
- 活动到期后，**最多5分钟内**就会自动切换
- 例如：活动在 00:03 到期，最晚在 00:08 就会切换

**其他选择：**
- **1分钟**：更精确，但检查更频繁（资源消耗稍多）
- **10分钟**：检查较少，但切换可能延迟（资源消耗更少）
- **1小时**：检查很少，但切换延迟较大（不推荐）

**推荐：**
- **5分钟**：平衡了精确度和资源消耗
- 对于活动切换来说，5分钟的延迟是可以接受的

## 🎯 实际效果对比

### 场景：活动在每月1日 00:00:00 到期

#### 使用定时任务（方式A）
```
00:00:00 - 活动到期
00:00:05 - 定时任务检查 → 发现活动已到期 → 自动切换 ✅
```
**结果：** 活动在 00:00:05 自动切换（延迟5秒）

#### 使用请求时检查（方式B）
```
00:00:00 - 活动到期
...（没有人访问）
08:30:00 - 第一个用户访问 → 检查 → 发现活动已到期 → 切换 ✅
```
**结果：** 活动在 08:30:00 才切换（延迟8.5小时）

## 📝 总结

**"定时任务，每5分钟检查一次"** 的意思是：

1. **后台自动运行**：不需要用户操作，系统自动运行
2. **每5分钟检查**：每隔5分钟，系统会自动检查一次活动是否到期
3. **自动切换**：如果发现活动已到期，自动切换到下一个活动
4. **精确控制**：可以精确控制活动切换时间（最多延迟5分钟）

**简单理解：**
就像设置了一个闹钟，每5分钟响一次，提醒系统检查活动是否到期，如果到期了就自动切换。

## ❓ 常见问题

### Q1: 定时任务会影响服务器性能吗？
**A:** 不会。检查活动是否到期是一个非常简单的操作，只需要几毫秒，不会影响性能。

### Q2: 如果服务器重启了，定时任务会丢失吗？
**A:** 不会。定时任务会在服务器启动时自动重新创建。

### Q3: 可以调整检查频率吗？
**A:** 可以。可以设置为1分钟、10分钟等，根据需求调整。

### Q4: 定时任务需要额外的服务器吗？
**A:** 不需要。定时任务在现有服务器上运行，不需要额外的服务器。
